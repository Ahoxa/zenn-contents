# UIライブラリを作る上で知っておきたいこと
一歩踏み出してくれてありがとう。一緒にがんばりましょう。
では早速参ります。

UIライブラリでは次のような環境、最低限ライブラリが必要です。
- `workspace`（`npm`, `yarn`, `pnpm`, `bun`）
- `tsup`（`rollup`や`vite build`でも🆗）
- `changeset`
- `storybook`
- `Vitest`
- CSS系ライブラリ（`tailwind`など）

これで最低限のUIライブラリを作成することができます。
この他にも
- `size-limit`
- `jest-axe`

なんかもありますが、ここらになると話が煩雑になるのであとで触れることにして、上のCSS系を除いた5つについて説明します。
storybookやVitestの詳しい話はかなり語ることが多いので、専用の章を設けてそこで紹介しています。必要に応じて読み飛ばしてください。

## workspace
これは特に説明は不要なんじゃないかと思いますが、一応念の為。
workspaceはライブラリじゃないのですが、スタックという側面からみて同じくくりで話します。

UIライブラリのリポジトリは多くのディレクトリで構成され、それぞれの
ディレクトリで独自の依存関係を持ちます。
例えば、ahouiのディレクトリ構成はこんな感じです。

```
ui-lib/
├─ packages/
│  ├─ core/      # FW非依存のヘッドレス
│  ├─ react/     # Reactアダプタ
│  ├─ solid/     # Solidアダプタ
│  └─ styles/    # vanilla-extract
├─ apps/
│  ├─ docs-react/  # Storybook for React
│  └─ docs-solid/  # Storybook for Solid
├─ package.json
├─ tsconfig.base.json
└─ .changeset/
```
これらそれぞれのディレクトリがそれぞれ`package.json`を持つので、管理が大変です。
そこで`workspace`の登場ってわけです。

`workspace`は依存関係をルートでまとめて管理できるため、開発効率が高く、ビルド・Lint・テストの統一もできてしまう環境と言えるでしょう。インストールの際もRootでコマンドを一発叩けばいいのでとっても楽です。
この流れでは`workspace`はライブラリ開発専用かと思われてしまうかもしれませんが、monorepo開発で多く用いられます。

## tsup
私はこれ、ahouiを作るまで知りませんでした。
`tsup`は、TypeScript製のライブラリを最終的に配布可能な形（npm で使える形）に変換するためのビルドツールです。

UIライブラリ開発において、開発中のコードは TypeScript・JSX・CSSなどさまざまな形式で書かれていますがnpmで配布できるのは最終的にビルドされた、JavaScriptと型定義ファイルだけ。

その変換を自動化してくれるのが`tsup`くんです。
もう自動化ってだけで好きになっちゃう。全部やってくれ。頼むからビルドエラーを吐かないでくれ。泣いちゃうから。

こいつを使うことで、
- 利用者が `import { Button } from "@ahoui/react"`でUIを呼び出せるようになったり...
- Tree Shakingによって副作用を抑えたり...
- ESM/CJSの互換性を保ったり...

これだけ見てもたくさんのことができるようになります。
これで軽量で早いんだからもう絶対に入れましょう！！
