### bun-workspaceを作る
というわけでまずは`workspace`を立てましょう。
ahouiの開発では`bun`を採用しているので`bun`で`workspace`を作っていきます。

もしこれから始めるのなら、`bun`か`pnpm`あたりをお勧めします。
ここでは`pnpm`での作り方は扱いませんので、`pnpm-workspace`の立て方をわかりやすく解説した記事を貼っておきます。
https://zenn.dev/wakamsha/articles/construct-monorepo-with-pnpm

まずは`init`コマンドをプロジェクトルートで叩きます。
```zsh
bun init
```
すると、画像のような状態になるので、`Library`を選択しましょう。
![](https://storage.googleapis.com/zenn-user-upload/dd6697b0e5a4-20251101.png)

次に`package name`を聞かれると思いますが、すでにリポジトリをクローンして`current directory`がプロジェクトルートなら何も入力せずに**Enterを強めに叩きましょう。**
そしてEntry Pointですが、これもなにも考えずにEnter強打で結構です。ahouiに限らず、複数`package`をもつ構成にする際は不要ですのでこの後消します。

![](https://storage.googleapis.com/zenn-user-upload/ad9f69de2fa4-20251101.png)

さて、無事インストールなどが終わり、ファイルなどが追加されましたか？
`package.json`を次のように修正すれば`bun-workspace`の完成です。楽ちんですね。

```json: package.json
{
  "name": "あなたのOSSの名前",
  "author": "あなたの名前",
  "private": true,
  "workspaces": [
    "packages/*" // あなたのディレクトリ構成に応じて変えてください
  ],
  "scripts": {},
}
```

### プロジェクトRootに開発に必要なライブラリをインストールする

### tsconfigをライブラリ開発用にする
次に`tsconfig`を書いていきます。ビルドには`tsup`を使うのでここで定義するのはビルドには関係のない部分を中心に指定します。ahouiではこのようなオプションを設定しました。
最近はAIがやってくれることも多いと思いますが、各オプションがどのようなことを扱うのかしっかり理解して設定しましょう。

:::details tsconfig
```json: tsconfig.json
{
  "compilerOptions": {
    // Environment setup
    "baseUrl": ".",
    "paths": {
      "@ahoui/*": ["packages/*/src"]
    },
    "target": "ESNext",
    "lib": ["ESNext", "DOM", "DOM.Iterable"],
    "module": "Preserve",
    "moduleDetection": "force",
    "jsx": "react-jsx",

    // Bundler settings
    "moduleResolution": "bundler",
    "verbatimModuleSyntax": true,
    "noEmit": true,
    "isolatedModules": true,
    "esModuleInterop": true,
    "resolveJsonModule": true,

    // type practices
    "strict": true,
    "skipLibCheck": true,
    "noFallthroughCasesInSwitch": true,
    "noUncheckedIndexedAccess": true,
    "noImplicitOverride": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true,
    "noPropertyAccessFromIndexSignature": false,

    // Project references
    "composite": true,
    "incremental": true,
    "tsBuildInfoFile": "./dist/tsbuildinfo"
  },
  "include": ["packages"],
  "exclude": ["dist", "node_modules", "**/*.test.ts", "**/*.spec.ts"]
}

```
:::

ポイントに絞ってオプションについて軽く説明します。
詳しくはこちらを参照してください
https://www.typescriptlang.org/tsconfig/

:::details tsconfigオプションの説明
#### module: "Preserve"
- インポート/エクスポート文を元のまま保持
- バンドラーがモジュール形式を決定

#### moduleDetection: "force"
- すべてのファイルをモジュールとして扱う
- グローバルスコープの汚染を防ぐ

### verbatimModuleSyntax: true
- import type と import を厳密に区別するので、型のみのインポートを明示的に書く必要がある
- バンドルサイズ削減とツリーシェイキングに貢献

#### noEmit: true
- TypeScriptコンパイラはJSファイルを出力しない
- ahouiは`tsup`がビルドを担当するので、TypeScriptは型チェックとエディタ補完のみに使用

#### isolatedModules: true
- 各ファイルを独立してトランスパイル可能にする
- `Babel`、`esbuild`、`tsup`などの高速トランスパイラに必須

#### "noPropertyAccessFromIndexSignature": false
- インデックスシグネチャのプロパティに `.` でアクセス可能

#### composite: true
- モノレポで必須
- パッケージ間の依存関係をtscが理解できるようにする

#### incremental: true
- ビルド情報を`.tsbuildinfo`に保存し、変更されたファイルのみ再チェックすることでビルド時間を大幅に短縮することができる神設定
:::

### packages配下に各ディレクトリを切る
さて、このチャプター最後のトピックです。
ライブラリの骨子となる、packagesディレクトリに実装するための設定を行います。
おさらいですが、`@ahoui/packages`以下のディレクトリ構成は以下のようにしました。
```
packages
├─ core // ahouiのベース。振る舞いやスタイルを定義
│  ├─ src
│  ├─ package.json
│  └─ tsup.config
├─ react // coreをもとにReact用のコンポーネントにする
└─ solid // coreをもとにSolid用のコンポーネントにする
```
ここではcoreとreactのみについて説明します。
詳しくはahouiのリポジトリを参照してください

まずディレクトリを切ってファイルを追加します。
その次に各ディレクトリに`package.json`と`tsup.config.ts`を追加します。`index.ts`はまだ空で大丈夫です。

#### core/package.jsonの設定
```json:core/package.json
{
  "name": "@ahoui/core",
  "version": "0.0.0",
  "type": "module",
  "main": "./dist/index.cjs",
  "module": "./dist/index.mjs",
  "types": "./dist/index.d.ts",
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/index.mjs",
      "require": "./dist/index.cjs"
    }
  },
  "sideEffects": [
    "**/*.css.ts",
    "**/*.css.js"
  ],
  "scripts": {
    "build": "bunx tsup"
  }
}
```
この本の読者のみなさんなら「`exports`はビルドしたファイルをどこに置くかの指定であること」などはお分かりだと思うので割愛します。

ここで重要なのは`sideEffects`です。
ahouiではスタイリングに`vanilla-extract`を採用しています。
`vanilla-extract`で生成される`.css.ts`ファイルはCSSを生成するため副作用があります。`Tree-shaking`で誤って削除されないようするために`sideEffects`にCSSファイルを指定しています。

#### core/tsup.config.jsonの設定
```json:core/tsup.config.json
import { defineConfig } from "tsup";
import { vanillaExtractPlugin } from "@vanilla-extract/esbuild-plugin";

export default defineConfig({
  entry: ["src/index.ts"],
  format: ["esm", "cjs"],
  dts: true,
  clean: true,
  treeshake: true,
  sourcemap: true,
  esbuildPlugins: [
    vanillaExtractPlugin({
      identifiers: "short",
    }),
  ],
});
```
tsupはスクリプトによってオプションを指定できるのが強みの一つでありますが、オプション追加のたびにスクリプトを見直すよりもconfigファイルに明記したほうがわかりやすいのでこのようにしています。
`esbuildPlugins`については`vanilla-extract`でスタイリングを行う都合上記述しています。ここは私もわからなかったのでAIに聞きました。

注意すべきは`souceMap`です
`sourceMap`を`true`にするメリデメは次のようになります。
開発時とビルド時で切り替えるのもアリです。

- メリット
    - デバッグが容易になる
        - ブラウザの開発者ツールでエラーが発生した際、ビルド後のコード（`dist/index.mjs`）ではなく、元のソースコード（`src/button.css.ts`など）の行番号が表示される
    - スタイルのトレースが可能
        - vanilla-extractで生成されたCSSが、どのソースファイルから来たのか追跡できる
    - 本番環境でのエラー追跡
        - Sentryなどエラーレポートツールで元のソースコードを参照できる
 
- デメリット
    - `.map`ファイルが生成されるのでビルドサイズが若干増加
